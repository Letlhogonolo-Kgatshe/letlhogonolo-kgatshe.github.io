The problem

Students in Cape Town trade tutoring, lifts and favours through scattered WhatsApp groups. There is no way to see who is offering what, whether a driver can be trusted, or what you have signed up for this week. I wanted one app for finding services, sharing rides and talking to the people involved.

What I built

  • A services marketplace where students offer, edit and book tutoring, tech help, design and errands, with ratings, reviews and an appointment-style booking flow.
  • A transport board laid out like Uber: a full-screen map, From/To search, routes drawn with OSRM, and one-off trips or regular carpools in a bottom sheet. Only verified drivers can offer rides.
  • Live, per-person messaging with edit, delete, block and report, and a planner-style home with the week's plan, points and badges.
  • Sign-in with email, Google (Credential Manager) or fingerprint, an optional app lock, notification switches per event and departure reminders that fire even when the app is closed.
  • An admin side that reviews reports and approves or revokes drivers after an in-person check, plus a small Node/TypeScript API for push notifications.

Key decisions

Offline first

Firestore's on-device cache serves saved data with no connection and queues writes, uploading them on reconnect. The app shows an offline banner and marks messages as "Sending…".

Trust before transport

Rides can only be offered by drivers an admin has approved, and an admin can revoke that status. Security rules on Firestore enforce who can read and change each record.

No secrets in the repo

The shared password for the sample accounts is read from an environment variable when the seed runs, so it is never committed.

Results

  • Final POE version 1.0.0, with a full walkthrough on video.
  • 126 Android and 111 backend unit tests run by GitHub Actions on every push.
  • Runs in English, Afrikaans and Setswana, switchable at runtime.
