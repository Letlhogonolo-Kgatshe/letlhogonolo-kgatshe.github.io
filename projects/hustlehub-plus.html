The problem

Freelancers and clients need a place to list gigs, book them and pay, but a marketplace that handles accounts and money is a target. The brief was to build one that is secure by design, prove it with tests and scans, and show freelancers what they earn after tax.

What I built

  • Built with Funi, Nomsa and Kwethukubonga. Clients browse and book gigs with simulated payments, freelancers manage their own gigs, and admins see all users and bookings.
  • My part: the freelancer income dashboard, with monthly income and income-against-tax charts and their tests.
  • My part: the Postman collection run with Newman in CI, covering bookings, income and tax, admin access and the security headers.
  • My part: security fixes for login and sessions: logins take the same time for unknown emails, passwords must be 12 or more characters and no more than 72 bytes, and logging out ends every session.
  • I also merged each member's final POE work into the release and wrote the dashboard and final POE sections of the README.

Key decisions

The role comes from the database

The user is loaded on every request, so a changed role or a deleted account takes effect immediately instead of when the token expires.

Tax worked out on the server

The SARS 2026/27 brackets live in one frozen config file. Income is read from the freelancer's own transactions inside the database query, and no amount from the request is trusted.

Security checks in the pipeline

Every push runs ESLint, Semgrep and npm audit next to the tests, and the API sets CSP and other security headers, rate-limits requests and runs over HTTPS in Docker.

Results

  • Newman: 124 requests and 176 assertions, none failing.
  • 80 frontend tests and 50 API unit tests.
  • Final POE delivered with a demo video, 9 November 2026.
